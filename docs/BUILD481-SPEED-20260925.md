## 逐帧复核后的门禁修正

逐帧 OCR 发现 8× 正式成片虽有 90/90 帧，却把按计划倍率预期的源帧
`0,8,16,…,712` 映射成 `0,7,15,24,31,39,…,711`；尚缺独立官方 GUI
逐帧对照来判断其编辑器采样语义。0.1× 和 0.5× 的末帧还分别落在所声明
源区间的右边界：0.1× 的最后 9 帧为源 frame 9，源区间是 `[0,9)`；
0.5× 的末帧为源 frame 45，区间是 `[0,45)`。现有 0.75× 混速项目

诊断证据，不再作为开放依据。逐帧数据见

## 1× 基线逐帧专项与 2×/60fps 诊断候选

`isom` H.264/AAC、3 秒、90/90 帧、完整解码，源 build 未变。
将成片 90 帧全部抽出并用 macOS Vision 识别，90 个时码均可读，源帧号
逐帧恰为 `0,1,2,…,89`，没有错位。输出 SHA-256 为
`9558848a4318fec835dd10143ca6b651e16fd0a5b57b0724a2a7b4e61cb86848`；

Skill 成功登记首页、四镜像一致；随后尝试 GUI 冷重开时发现 macOS 会话已锁屏，

验收明确记为失败，不能算作新的冷重开证据。已启动的剪映进程随后正常结束，
隔离草稿再次结构验证通过。`gui-cycle` 新增启动前锁屏拒绝。

解锁后发现 `CGSessionCopyCurrentDictionary` 在**已解锁**状态下会省略
`CGSSessionScreenIsLocked` 字段，修正预检为核对已登录控制台会话且仅在锁定字段
明确为真时拒绝。随后同一 1× 隔离草稿经已安装 Skill 的正式 `gui-cycle`
完成一轮打开、保存、正常退出、冷启动重开和最终正常退出；预检、打开、

剪映主进程最终不存在。后续发现旧 `gui-cycle` 仅核对时间线节点和目标
草稿磁盘状态，未独立回读编辑器中的草稿名称/绝对保存路径，故该
`verified` **不能单独证明打开了指定的 1× 工程**；正式 `gui-cycle`
曾失败关闭，需身份门修复后重做。随后已补入当前窗口名称 OCR 与活动 PID
的工程锁/资源路径双重身份检查，保存前再次读取目标句柄；已安装 Skill 对
1×、2× 隔离工程各完成三轮 GUI 保存/冷重开，最终保存门对两者各另通过
一轮。证据见 `work/build481-identity-final-{1x,2x}-3rounds-20260926/`
和 `work/build481-identity-saveguard-{1x,2x}-20260926/`。这些仅是 GUI
